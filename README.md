# StoryForge

> **Your idea. Your coordinate. Your techniques. One report.**
>
> 输入一段构想，获得跨文学坐标的叙事框架分析报告，涵盖故事架构、人物关系、命名方案、技法组合、思想内核。
>
> 从《剑来》式精品网文到马伯庸式历史知识小说，从《三体》式思辨科幻到《嫌疑人X的献身》式深度推理，再到茅盾文学奖式严肃文学——同一个构想，在不同坐标下呈现不同的可能性。
>
> 一键导出结构化 PDF 分析报告。

## 核心功能

- **四层文学坐标**：精品网文取向 / 历史知识叙事取向 / 思辨类型取向 / 严肃文学取向——不含纯爽文取向，所有坐标都指向「有思想深度与艺术追求」的创作
- **三层数据模型**：文学坐标（创作追求与约束）× 题材库（母题与人物原型）× 技法库（43 条技法，按坐标亲和度筛选注入）
- **十节结构化报告**：构想概述与坐标定位、题材与母题、故事主体架构、人物关系图（Mermaid 可视化）、核心人物设定与命名方案、三套技法组合方案（含 200-300 字文学级示范片段）、思想内核分析、坐标专属创作要点、参考作品对标、下一步建议
- **BYOK 多模型支持**：DeepSeek / Kimi / OpenAI / 任意 OpenAI 兼容端点，界面内配置、随时切换、一键测试连接
- **多模态输入**：可上传情绪板 / 手写笔记照片作为参考（视觉模型）
- **自定义技法注入**：个人技法库 + AI 质量校验，生成报告时自动注入上下文
- **PDF 一键导出**：保留完整排版与 Mermaid 关系图，文件名自动带作品名与日期
- **本地历史记录**：每次生成自动存入浏览器 IndexedDB，可随时回看、重新导出、删除

## 快速开始

```bash
npm install
npm run dev
```

打开 http://localhost:3000 即可。**无需 `.env`，无需任何环境变量。**

首次打开会强制弹出「模型设置」面板，填入你的提供商、Base URL、模型名和 API Key，点击「测试连接」验证后即可开始使用。

## BYOK 说明

**你的 API Key 仅存储在浏览器本地（IndexedDB），请求时经由本应用的服务端转发一次，不会被记录或存储。如不信任部署方，建议自行部署。**

- 后端（`app/api/*/route.ts`）只是通用转发器：Key 只出现在单次请求的 `Authorization` 头中，不写入日志、不写数据库、不持久化
- 项目不包含 `.env` 文件，Vercel 部署时也不需要配置任何环境变量
- 服务端代码完全开源，转发逻辑不足百行，可自行审计

## 设计原则

1. **不服务纯爽文**：任何坐标下都不推荐「以即时爽感为唯一目标」的技法组合
2. **思想深度是底线**：推理的终点是「为什么人会这样做」，科幻的终点是「人在宇宙中的位置」，技法永远服务于思想表达而非情节刺激
3. **AI 输出是报告，不是数据**：最终产物是一份结构化 Markdown 分析报告，前端渲染、一键导出 PDF

## 技术架构

```
┌────────────────────────────────────────────────────────┐
│                     浏览器（客户端）                     │
│  ┌─────────────┐  ┌──────────────┐  ┌────────────────┐ │
│  │ 输入面板     │  │ 报告预览      │  │ IndexedDB      │ │
│  │ 构想/坐标/   │→ │ Markdown 渲染 │  │ settings       │ │
│  │ 题材/图片    │  │ Mermaid 图   │  │ customTechniques│ │
│  └──────┬──────┘  │ html2pdf 导出│  │ history        │ │
│         │         └──────────────┘  └────────────────┘ │
└─────────┼──────────────────────────────────────────────┘
          │ POST /api/analyze（携带 modelConfig，Key 仅本次使用）
          ▼
┌────────────────────────────────────────────────────────┐
│           Next.js API Route（Serverless 转发器）         │
│  构建 system prompt（坐标+题材+技法+模板） → 转发请求     │
│  不存储、不记录 API Key                                  │
└─────────┬──────────────────────────────────────────────┘
          │ OpenAI 兼容协议 /chat/completions
          ▼
┌────────────────────────────────────────────────────────┐
│     DeepSeek / Kimi / OpenAI / 任意兼容端点（用户自选）   │
└────────────────────────────────────────────────────────┘
```

**技术栈**：Next.js 14（App Router）· TypeScript · Tailwind CSS · react-markdown + remark-gfm · mermaid · html2pdf.js · idb（IndexedDB）

## 项目结构

```
├── app/
│   ├── page.tsx                  # 主界面（输入 + 报告）
│   ├── history/page.tsx          # 历史记录页
│   ├── layout.tsx
│   ├── globals.css               # 深色主题 + Markdown 排版
│   └── api/
│       ├── analyze/route.ts              # 报告生成转发
│       ├── test-connection/route.ts      # 模型连通性测试
│       └── validate-technique/route.ts   # 自定义技法 AI 校验
├── components/                   # 9 个 UI 组件
├── lib/
│   ├── constants.ts              # 文学坐标 / 题材库 / 技法库 / 提供商
│   ├── prompts.ts                # system prompt 构建（含十节模板）
│   ├── db.ts                     # IndexedDB 封装
│   ├── types.ts                  # 全局类型
│   └── utils.ts
└── types/html2pdf.d.ts
```

## 部署（Vercel）

1. 将仓库推送到 GitHub
2. 在 Vercel 导入项目，直接 Deploy——**无需配置任何环境变量**
3. 部署完成后，每个使用者在自己的浏览器中配置自己的 API Key
